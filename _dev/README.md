# Supermemory — слоистая память для Claude Code

Персистентная память для Claude Code, в которой факты **никогда не теряют качество**: при разрастании они не сжимаются с потерями, а сдвигаются на слой глубже, оставляя наверху выжимку со ссылкой вниз. На любом слое видно, какие факты есть на этом уровне и что можно копнуть глубже.

Ментальная модель — LSM-дерево: записи падают в верхний слой, компакция сливает и сдвигает вниз, чтение идёт сверху с возможностью спуска.

## Как устроено хранилище

Директория `supermemory/` в корне воркспейса. **Слой = глубина директории**:

```
supermemory/
  index.md                      ← L0: всегда в контексте Claude (через @import в CLAUDE.md)
  ab-tests/                     ← блок, компактнутый на слой вниз
    index.md                    ← выжимка блока: по строке-крючку на каждый факт
    decision-piggyback.md       ← факт целиком, как был записан
    experiment-refactor.md
  migration-up-down-up-test.md  ← свежий факт, ещё не компактнутый — живёт у корня
  audit.sh                      ← механическая проверка инвариантов
```

- Каждая директория — блок; её `index.md` — выжимка содержимого; файлы — факты; поддиректории — блоки уровнем глубже.
- Строки индекса: `↓ блок/ — крючок` (есть детали глубже) и `• файл.md — крючок` (факт этого уровня). Первый токен после маркера — точное имя ребёнка: по нему работает audit.
- Файл факта: frontmatter (`id`, `scope`, `status`, `updated`, `hooks` — ключевые слова для grep, опц. `pinned`) + тело с `**Why:**` и `**How to apply:**`.
- Бюджет любого `index.md` — 40 строк. Превысил — пора компактить.

## Установка (3 шага)

1. Сохранить Приложение A как `~/.claude/skills/supermemory/SKILL.md`.
2. В корне воркспейса: `mkdir supermemory`, создать `supermemory/index.md` (минимум — заголовок и строка с нотацией, см. пример ниже), сохранить Приложение B как `supermemory/audit.sh`, сделать `chmod +x`.
3. В корневой `CLAUDE.md` воркспейса добавить секцию:

```markdown
## Supermemory (персистентная память воркспейса)

Слоистая память в `supermemory/` — скилл `/supermemory`. Ниже импортирован её L0-индекс.
Если задача задевает тему из индекса — сначала прочитай index.md соответствующего блока
(спуск по ↓), потом работай. Новые долговременные факты — по процедуре скилла, не в этот файл.

@supermemory/index.md
```

`@путь` — это import-механизм CLAUDE.md: содержимое L0 попадает в контекст каждой сессии автоматически.

Стартовый `index.md`:

```markdown
# Supermemory — L0

Нотация: `↓ блок/` — есть выжимка и детали глубже; `• файл.md` — факт этого уровня.
Бюджет индекса — 40 строк; при переполнении — компакция (скилл /supermemory).
```

## Ежедневное использование

Всё делается словами, Claude выполняет процедуры из скилла:

- **«Запомни: …»** — Claude кладёт факт файлом в корень стора и добавляет строку в L0. Новое всегда пишется наверх; вглубь факты попадают только компакцией, когда остывают.
- **Recall — автоматический.** L0 всегда в контексте; если задача касается темы из индекса, Claude читает `index.md` нужного блока и спускается дальше, пока крючки обещают релевантное. Запасной путь — `grep -ri <слово> supermemory/` (для этого у фактов поле `hooks`).
- **`/supermemory compact`** — когда индекс распух: Claude группирует связанные факты в поддиректорию, пишет ей выжимку, заменяет N строк родителя одной. Тела фактов при этом не переписываются — потерь нет.
- **Промоция / pin** — часто нужный факт поднимается на слой выше; `pinned: true` защищает от демоции.
- **`/supermemory audit`** (или `supermemory/audit.sh` руками) — проверка инвариантов: у каждого блока есть выжимка, все дети упомянуты, ссылки не битые, бюджеты соблюдены, нет устаревших выжимок.

## Правила (что делает схему «без потерь»)

1. **Ничего не удаляется** — только сдвиг вниз или пометка `status: superseded: <id>`. Если стор под git, история — нулевой слой.
2. **Тела фактов неприкосновенны при сдвиге** — новая проза появляется только в выжимках.
3. Противоречие с существующим фактом — правка старого по месту, а не молчаливый дубль на другом слое.
4. Правишь факт — обновляй выжимки предков; если отложил, ставь в их `index.md` маркер `<!-- DIRTY -->`, audit напомнит.
5. Жёсткие always-on правила («никогда не делай X») — **не** supermemory: им место прямо в CLAUDE.md, потому что спуск за ними может не случиться. Supermemory — для знаний-справок, которые нужны иногда.

## Экономика токенов

CLAUDE.md оплачивается целиком в каждой сессии. Если складывать знания туда, постоянная стоимость растёт линейно с объёмом памяти: 50 фактов по ~150 токенов = ~7500 токенов в каждой сессии, нужны они или нет.

Со слоями в каждой сессии всегда оплачивается только L0 (~300–500 токенов), а факт со дна подтягивается одним Read (~100–300 токенов) — и только когда реально нужен. Рост памяти почти не увеличивает постоянную стоимость: новый факт — это одна строка в индексе, тело живёт вне контекста.

Обратная сторона: recall стоит 1–2 Read, и если факт нужен в каждой сессии — дешевле (и надёжнее) держать его always-on в CLAUDE.md или L0. Отсюда правило 5.

## Известные слабости

- **Дрейф выжимок**: факт поправили на глубине — выжимки выше могут врать. Лечится дисциплиной DIRTY-маркеров + audit.
- **Кластеризация при компакции** — решение модели, иногда спорное. Смягчается обратимостью (промоция + перегруппировка) и неприкосновенностью тел.
- Автоматический recall харнеса на кастомную директорию не распространяется — спуск держится на инструкции в CLAUDE.md и триггерах скилла.

````markdown
# Supermemory — слоистая память без потерь

Стор — директория `supermemory/` рядом с CLAUDE.md, который импортирует её `index.md`. Модель — LSM-дерево для фактов: новое пишется в верхний слой, компакция ничего не удаляет, а сдвигает вниз, чтение — спуск сверху.

## Структура

- **Слой = глубина директории.** Каждая директория — блок; её `index.md` — выжимка блока; файлы `*.md` — факты; поддиректории — компактнутые блоки уровнем глубже.
- Корневой `index.md` — L0, всегда в контексте (через `@supermemory/index.md` в CLAUDE.md).
- Строки индекса: `↓ блок/ — крючок` (можно копнуть глубже) и `• файл.md — крючок` (факт этого уровня). Первый токен после маркера — точное имя ребёнка, по нему работает audit.
- Файл факта: frontmatter `id, scope, status (active | superseded: <id>), updated, hooks (ключевые слова для grep), pinned (опц.)` + тело: факт, `**Why:**`, `**How to apply:**`.
- Бюджет любого `index.md` — 40 строк.

## Операции

### remember — новый факт
Всегда в верхний слой: файл `<slug>.md` в корень стора + строка `• <slug>.md — крючок` в L0. Никогда не класть новый факт сразу вглубь — туда его сдвинет компакция, когда остынет. Сначала grep по hooks: если факт уточняет существующий — правь тот по месту; если противоречит — правь или ставь старому `status: superseded: <new-id>`. Молчаливый дубль на другом слое запрещён.

### recall — спуск
L0 уже в контексте. Если задача задевает тему строки — прочитай `index.md` блока за `↓`, спускайся, пока крючки обещают релевантное (обычно 1–2 Read). Второй путь: `grep -ri <keyword> supermemory/` — поле hooks для этого и существует.

### compact — сдвиг вниз
Триггер: `index.md` превысил 40 строк, или явная просьба. Выбрать кластер связанных записей → `mkdir` → перенести файлы внутрь → написать новому блоку `index.md` (по строке-крючку на каждого ребёнка) → заменить их строки в родительском индексе одной `↓ блок/ — крючок`. **Тела фактов при сдвиге не переписываются** — новая проза появляется только в выжимке.

### promote / pin
Постоянно востребованный факт поднимай на слой выше: перенос файла + строка в верхнем индексе, убрать строку из нижнего. `pinned: true` = не демотировать из текущего слоя. Жёсткие always-on правила («никогда не делай X») — не supermemory, им место прямо в CLAUDE.md: спуск за ними рискует не случиться.

### audit
`supermemory/audit.sh [store]` проверяет механические инварианты: у каждого блока есть `index.md`; каждый ребёнок упомянут в выжимке родителя; упоминания не битые; бюджеты; маркеры `DIRTY`. Гонять после compact/promote.

## Инварианты

1. Ничего не удаляется — только сдвигается вниз или помечается superseded (если стор под git, история — нулевой слой).
2. Отредактировал факт — сразу обнови выжимки всех предков; если правка большая и выжимки отложены, поставь в их `index.md` строку `<!-- DIRTY -->`, чтобы audit напомнил.
3. Каждый ребёнок директории имеет строку в её `index.md`; L0 отражает всё на один уровень вниз.
4. `README.md` и `audit.sh` — служебные, в индексах не упоминаются.
````

## Приложение B: `supermemory/audit.sh`

```bash
#!/usr/bin/env bash
# Проверка инвариантов supermemory-стора. Использование: audit.sh [store_dir]
set -u
STORE="${1:-$HOME/home/supermemory}"
BUDGET=40
problems=0
note() { echo "FAIL: $1"; problems=$((problems+1)); }

[ -f "$STORE/index.md" ] || { echo "FAIL: нет корневого index.md в $STORE"; exit 1; }

# у каждого блока есть выжимка
while IFS= read -r d; do
    [ -f "$d/index.md" ] || note "нет index.md: $d"
done < <(find "$STORE" -mindepth 1 -type d)

while IFS= read -r idx; do
    dir=$(dirname "$idx")

    lines=$(grep -c '' "$idx")
    if [ "$lines" -gt "$BUDGET" ]; then
        note "превышен бюджет ($lines > $BUDGET строк) — пора компактить: $idx"
    fi

    if grep -q 'DIRTY' "$idx"; then
        note "устаревшая выжимка (ребёнок менялся): перечитай детей, обнови выжимку, убери маркер: $idx"
    fi

    # каждый ребёнок на диске упомянут в выжимке
    while IFS= read -r child; do
        name=$(basename "$child")
        case "$name" in index.md|README.md|audit.sh|.*) continue ;; esac
        [ -d "$child" ] && name="$name/"
        grep -qF "$name" "$idx" || note "ребёнок не упомянут в $idx: $name"
    done < <(find "$dir" -mindepth 1 -maxdepth 1 \( -name '*.md' -o -type d \))

    # каждое упоминание существует
    while IFS= read -r m; do
        [ -e "$dir/$m" ] || note "битая ссылка в $idx: $m"
    done < <(grep -E '^(↓|•) ' "$idx" | awk '{print $2}')
done < <(find "$STORE" -name index.md)

if [ "$problems" -eq 0 ]; then
    facts=$(find "$STORE" -name '*.md' ! -name index.md ! -name README.md | grep -c '')
    echo "OK: инварианты соблюдены (фактов: $facts)"
else
    echo "Проблем: $problems"
    exit 1
fi
```
